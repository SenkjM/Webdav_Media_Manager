# 00 · 文档索引与项目约定

面向人类开发者与 coding agents 的**唯一入口**。文档按「功能块」组织：每篇讲清一块功能对用户的语义、可观察行为，以及它在代码里的实现位置。**不写验收清单，不写过程记录。**

## 1. 文档怎么写、放哪

- 全部文档平铺在 `docs/`，文件名 `NN-NAME-IN-CAPS.md`（两位数字编号 + 大写英文名）。
- `00` 固定是本文件。其余按功能块递增，见下表。
- 新增文档：取下一个可用编号，在下表登记一行。**不要建子目录、不要用字母前缀、不要另立「归档 / 活跃」状态**——文档写的是现状；与代码冲突时以源码与测试为准，然后回来改文档。
- 想写计划，就写进对应功能块的文档里，并显式标注「计划（未实现）」。不要单开计划文档。
- `99` 固定是**开发中文档**，不参与功能块编号。

### 完整文档与开发中文档

- `01`–`09` 是**完整文档**：写的是现状；与代码冲突时以源码与测试为准，然后回来改文档。
- `99` 是**开发中文档**：只记录**正在开发**的功能的原始语义——需求原话、取舍、临时决定、还没定型的实现。
- 开发新功能时**先读 `99`**，再读它链到的完整文档。
- `99` 里每一条都要给出指向相关、或可能被这次改动影响的完整文档的链接。
- 开发期间：完整文档对应位置保留**占位**（一行说明 + 指向 `99` 的链接），不写半成品语义。
- 开发完成：删掉 `99` 里的那一条，把语义按完整文档的写法补进对应功能块，去掉占位。

## 3. Agent 编码约束

1. **先读本索引，再读对应功能块文档**；改动前确认它描述的就是现状。
2. **开发新功能前先读 [99](99-IN-PROGRESS.md)**，再读它链到的完整文档；开发期间同时维护 `99` 与完整文档里的占位，完成后按 §1 收口。
3. **分支**：`main` 是唯一主干，只有用户明确允许才可合并。新功能一律**基于 `main` 开独立功能分支**，成熟后**压缩成单个提交**合入 `main`（除非用户另有要求，例如要保留每一步的提交历史）。压缩后的提交信息要能独立说清整条分支做了什么。不开长期保存线，中途成果留在自己的功能分支上。
4. **CI**：不要为了看构建结果给 workflow 加 `on: push`，不要擅自 `gh workflow run`，不要推 `main`，不要打 Pre-release——除非用户明确要求。细节见 [09](09-MISC.md)。
5. **改完跑** `flutter analyze` 与相关 `flutter test`；改核心逻辑优先跑 [09](09-MISC.md) 列出的测试入口。
6. **密钥一律不打印、不提交**：keystore、`key.properties`、token、`.env`、secrets。
7. 提交信息用简短英文前缀（`feat:` / `fix:` / `docs:` / `deps:` / `ci:`）+ 说明。
8. UI 文案用中文，标识符 / 路径 / API 名保持英文。保持 AGPL-3.0 头。
9. **开始大工程或新功能前**：先做拆分，把适合顺手做的小任务写进 [10](10-SIDE-QUESTS.md)（写清来源、边界与判断条件），**并问用户是否要一起做**——发不发布、拆不拆、合不合并由用户定，agent 只列理由。判断标准与流程见架构技能 `task-splitting-and-side-quests`。

## 4. 项目整体规划

**定位**：Android-first 的 WebDAV 媒体客户端。音频「先下载到本地缓存再播放」，视频走远端流式播放，两者都不做「边下边播的隐式入队」。当前主线是稳定性与体验细节，不是新功能扩张。

**近期（进行中）**：见 [99 §1 未在真机验收](99-IN-PROGRESS.md)（代码已上 `main`、真机未验的清单）、[99 §5 主题配色](99-IN-PROGRESS.md) 与 [99 §6 多语言](99-IN-PROGRESS.md)（已分析、未开工）。仍在修的一个实名问题：[04](04-DOWNLOAD-QUEUE.md) 的「后台下载 `fail host lookup`」。

**路线图（规划快照，未排期，不要当成已实现能力）**：

- **WebDAV 管理**（高）：**复制 / 移动已做**（见 [02 §4](02-NETWORK-LIBRARY.md)）；仍缺上传、属性查看、回收站与覆盖冲突策略。已有新建文件夹、重命名、删除。
- **国产 ROM 媒体体验**（高）：ColorOS / 一加等机型的媒体通知与后台保活加固。
- **视频播放体验**（中）：缓冲进度条第二层、空闲自动隐藏控件、手势引导。
- **安装包体积**（中）：libmpv 编译裁剪，见 [06](06-VIDEO-PLAYBACK.md)。
- **同步体验**（中）：冲突可视化，云端分片整理与审计体验；格式约束见 [08](08-SYNC-AND-BACKUP.md)。
- **启动与低端机体验**（中）：压启动耗时与资源占用。
- **音乐输出后端**（低）：AudioTrack / AAudio 等可选输出后端；成本较高。
- **无障碍与多语言**（低）：语义标签、字号适配、多语言。
- **跨平台**（低）：iOS / 桌面端仅作远期评估，Android-first 不变。
