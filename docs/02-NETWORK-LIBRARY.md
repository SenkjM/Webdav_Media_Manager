# 02 · 网络库

> 编号 02 · 总索引：[00-INDEX.md](00-INDEX.md)  
> 代码：`lib/screens/network_library_screen.dart`、`lib/models/file_actions.dart`、`lib/screens/webdav_folder_picker_screen.dart`

网络库是 WebDAV 的浏览器：列目录、预览、把条目送进[下载队列](04-DOWNLOAD-QUEUE.md)或播放器。它**不是**曲库，也不代表本地有什么。

## 1. 核心约定：未下载 ≠「排队中」

- 用户没点过的远端文件处于 `TrackUiState.remote`：**不显示任何状态标签**，副标题写「点按下载」。
- 只有用户点按、多选或递归下载之后才入队，此时才出现「排队」「下载中」。
- 状态文案由 `lib/widgets/track_status_chip.dart` 统一给出：排队 / 下载中（带百分比）/ 就绪 / 播放中 / 错误；`remote` 返回空 widget。
- **不要**把「浏览时可见的远程文件」默认标成排队，也不要在播放路径上偷偷入队下载。

## 2. 文件动作模型

类型由后缀决定（[`FileTypeConfig`](01-DATA-MODEL.md)）：音乐 / 视频 / CUE / 普通文件。
每个类别在设置里有一个默认动作，格式为 `<类型> → <默认动作>`：

| 类别 | 默认动作 | 其它可选动作 |
|------|----------|--------------|
| 音乐 | 缓存音乐 | 流式传输（实验性，需开关）、下载 |
| 视频 | 流式传输 | 下载 |
| CUE | cue 读取 | 下载 |
| 普通文件 | 下载 | — |

- 「下载」= 落系统下载目录（`DownloadTarget.downloads`），**不是**缓存；音频缓存只由「缓存音乐」产生。
- 任何文件都可以用「下载」；缓存音乐只对音乐合法，视频那个流式传输只对视频合法。
- 判定只有一份实现：`FileActionCatalog.isAllowed` / `judgeAction`。动作与类型不匹配时**直接说明原因**，不静默换成别的动作。
- 三个入口共用同一份判定：整行点按、多选工具栏、右侧「更多」菜单。更多菜单的第一条永远是当前默认动作，并标注「设置里的默认动作」。
- 设置界面见 `file_extensions_screen.dart`：每个类别一个下拉框，选项就是上表的允许列表。

## 3. 行操作

| 操作 | 语义 |
|------|------|
| 点按文件行 | 执行该类别在设置里的默认动作（见 §2） |
| 点按已缓存音乐行 | 默认动作是缓存音乐时命中缓存即直接就绪，不会重下 |
| 点按文件夹 | 进入目录 |
| 点按 `.cue` | 默认动作是 cue 读取时进 CUE 预览流程，确认后整组下载（见 [03](03-MUSIC-LIBRARY.md)） |
| 长按任意行 | 进入多选 |
| 「⋮」·文件夹 | 「缓存文件夹中的音频」（递归扫描，音频进缓存）与「下载整个文件夹」（递归下载目录树，不挑类型）两条独立入口 |
| 行尾「⋮」 | 更多操作：默认动作 + 该类别的其它动作 + 重命名 / 复制到… / 移动到… / 删除 |
| 长按文件夹 | 递归下载整个目录里的音频 |

## 4. 复制 / 移动

- 入口：单行「⋮」→「复制到…」/「移动到…」，以及多选工具栏的复制 / 移动按钮（可批量）。
- 目标由目录选择器选出（`webdav_folder_picker_screen.dart`）：浏览远端目录树、可新建文件夹、可原地确认。
- 「当前服务器」下拉框（库页顶部的 `DropdownButtonFormField`）：`menuMaxHeight` 限成**半屏**，服务器多起来时菜单在里面滚动，不会顶出屏幕；`isExpanded: true` 让选中项撑满按钮宽度，长名字不会把菜单撑得比按钮宽。
- 选择器的按钮分工：**左上角是叉号（关闭选择器）**，右上角是**向上箭头（上一级，已在根目录时禁用）**与「新建文件夹」；返回键等价于上一级。顶部路径单行**可横向滚动**，长路径不会被省略号吃掉。
- 层级是**一格一格退**的：目录栈由 `remoteAncestors`（`lib/utils/remote_path.dart`）把当前目录展开成 `/a`、`/a/b`、`/a/b/c` 逐层压入，上一级与返回键各退一层，退到根目录再按才关闭选择器。曾经这里只把整条路径当成一层，于是打开选择器后点一次「上一级」就直接掉回根目录。
- **同名冲突自动改名**（`name (1).ext`），绝不静默覆盖——`Overwrite: T` 会不可逆地抹掉目标端旧文件。
- 移动文件夹时不能把它移进自己或自己的子目录（选择器禁用当前位置）。
- 传输层是 WebDAV 原生 `COPY` / `MOVE`（`WebDavService.copyPath` / `movePath`），远端自己完成，不经过本机。
- **已知限制（未做）**：移动 / 重命名远端文件后，本机音乐库里绑定旧路径的曲目不会自动跟随；重名解析需要先列一次目标目录（列目录失败时沿用原名，由服务端报错）。

## 5. 多选工具栏

- 长按进入多选；**点按行**在多选态下切换勾选，取消到最后一项时退出多选。
- 工具栏左端那个按钮是「全选」/「取消全选」，**判定用计数器对比**（选中数 == 可选总数即为全选），不看按钮按过没有：
  - 一进入多选它只是「全选」，**不显示叉号**；
  - 计数打满（无论按全选还是手动一项项点满）时它变成叉号，作用是**取消全选**，不是退出多选；
  - 任何一次手动取消都会把计数打回去，按钮随即变回「全选」。
  - 计数对比要成立，**总数必须跟着当前列表走**：`SelectionController.toggleSelectAll` 自己用传进来的 key 列表定 `total`。曾经这里只透传旧值，而音乐库从不调用 `sync`，`total` 永远是 0——`isAllSelected` 恒为假，于是「点了全选，再点多少遍还是全选」，按钮根本变不回来。
- 退出多选靠系统返回键（或点掉最后一项）。
- 「缓存音乐」与「下载」是**两条独立的线**，选中内容里有文件夹或文件都会同时出现，都**不挑个数**，图标都是固定的（缓存＝音乐、下载＝下载），不因选中内容换样子。曾经这里按「只选了一个文件夹」特判，多选文件夹时缓存按钮直接是灰的。
  - **缓存音乐**＝把选中内容里的音频收进缓存：选中的音频文件直接入队，选中的文件夹递归扫一遍再入队（随后 ingest 进音乐库）。**扫描是这条线内部的步骤**，对用户是同一个功能、同一个按钮，不另立入口。
  - **下载**是基本功能：不挑类型也不挑个数，文件夹递归全下——音频、视频、CUE 一律照下，**不跳过任何东西**。
  - 两者互不排斥：同一批内容两个都点就会各排一遍。
  - 复制到… / 移动到… 对任意选中项都可用。
- **没有播放按钮**：流式播放一次只能放一个，放个「播放全部」只会误导；要播就点那一行（或在「⋮」里选）。
- 工具栏外壳（底色、铺满整宽、横向滚动）是网络库与音乐库**共用的** `lib/widgets/selection_toolbar.dart`；里面的按钮与业务各写各的——两个库只有「多选」这件事通用。
- 铺满整宽必须用**具体**宽度（`constraints.maxWidth`）：横向滚动层给子级的宽度约束是无限的，那里写 `minWidth: double.infinity` 是不可满足约束，整条工具栏会直接不画（踩过一次）。
- 放进外壳的按钮里**不能用 `Expanded` / `Flexible` / `Spacer`**：它们要分配「剩余空间」，而横向滚动层里宽度无限，没有剩余空间可分，整条工具栏会在渲染时炸掉（音乐库这样炸过一次，`flutter analyze` 与测试都发现不了——只有跑起来才看得见）。文字用 `Padding` + `Text` 自然宽度。
- 下载与缓存职责分开，但都按「选中了什么」说话，不按类型把按钮变灰：缓存只收音频，下载什么都收。视频不自动塞进相册（相册在「⋮」里单独选）。
- **界面不分「文件夹那条路 / 文件那条路」**：两条线共用一个流程 `_queueSelection`，把选中的文件夹与文件一起交给 `DownloadQueueService.enqueueSelection(sourceName, folderPaths:, files:, target:)`。扫描、去重、入队全在服务层。
  - 这样才对：界面自己分路的话，一旦同时选中文件夹和里面的文件，同一个路径会从两个入口各排一次。
  - 服务层先把扫出来的路径与已选文件**按路径去重**，再按 **(来源, 路径, 目标)** 入队——所以「先点缓存再点下载」不会被上一条静默吞掉（只按路径去重就会）。
  - `enqueueSelection` 返回 `(ok, failed, scanned, firstError)`：**一个文件夹扫不动不拖垮其余的**，`scanned == 0` 说明文件夹本来就是空的。

## 6. 导航与返回键

- 进入子目录后按返回键 → 回父目录。
- **多选状态下按返回键 → 只退出多选**：既不回上一页，也不回主页。
- 已在根目录时按返回键 → 交给应用壳（切主页标签 / 挂后台）。
- 实现要点：网络库在 `initState` 里向 `BackHandlerRegistry` 注册处理器（`PopScope` 在这层嵌套导航里收不到事件）；音乐库的两个多选组件同样注册，并且只在**当前路由**上生效，否则父页面的处理器会先把事件消费掉。壳层的返回语义见 [05 §3](05-AUDIO-PLAYBACK.md)。

**列表加载失败的重试纪律**（真机反馈：crypt 源被删后应用被拖慢）：

- **导航动画先行**：进入 / 返回立即切路径并显示加载动画，请求带序号；迟到响应作废（`_loadSeq`），旧路径的结果绝不写进新路径的页面。
- **自动重试有上限**：连续失败 3 次（`_kMaxLoadFailures`）即停手，停在错误界面等用户手动「重试」；手动重试与成功加载都清零计数。
- **重入口必须防抖**：`_ensureAndLoad` 用 `_ensureInFlight` 防重入——加载失败不更新 `_browsedAccountId`，不防重入会让 build 守卫每帧重新调度一次，并发堆叠全量账号重建（这正是「无限重试拖慢运行」的成因）。
- **网络恢复可提前唤醒**：`connectivity_plus` 检测到恢复在线且当前停在耗尽态的错误界面时，重置计数并自动重试一次。

## 7. 下载目标（这里只决定「去哪儿」）

| 条目 | 目标 |
|------|------|
| 音频（缓存音乐） | 应用音频缓存，随后 ingest 进[音乐库](03-MUSIC-LIBRARY.md) |
| 视频（⋮ → 下载到系统相册） | 系统相册 `Movies/WebdavMediaManager`（MediaStore），不进音频缓存 |
| 任何文件（下载） | 系统下载目录（MediaStore `Downloads`） |

队列状态、进度通知与失败处理见 [04](04-DOWNLOAD-QUEUE.md) 与 [07](07-NOTIFICATIONS.md)。

## 8. 尚未实现 / 未验收

- **音乐流式传输**：实验开关打开后，音乐条目会复用视频的远端流管线直接播放（不下载、不缓存、不入队），界面是独立的[音乐流式播放页](05-AUDIO-PLAYBACK.md)（不渲染视频、无手势、控件不自动隐藏、不旋转、不画中画）。后缀被改掉、内容其实是音频的条目也会路由到这一页。封面与时长不取；流式的优化方向见 [99 §3](99-IN-PROGRESS.md)。
- **移动 / 重命名后库内路径不跟随**：远端文件被移动 / 重命名后，本机音乐库里绑定旧路径的曲目不会跟随，需要一次「路径重写」才能做对。
- **复制 / 移动没有进度与取消**：`webdav_client` 的 `copy` / `rename` 是单次请求，大文件只能等。
- **部分服务端的目录 `Destination` 处理不一致**（结尾 `/` 加不加），复制 / 移动到目录的目标要在真实网盘上各试一次。
- 上传、属性查看、批量覆盖冲突策略：见 [00 §4](00-INDEX.md) 路线图的「WebDAV 管理」。

## 9. 相关代码

- `network_library_screen.dart`：目录列表、多选、动作分发（`_runAction`）、CUE 入口。
- `lib/models/file_actions.dart`：动作模型、允许列表、判定与设置解析。
- `lib/screens/webdav_folder_picker_screen.dart`：目录选择器与复制 / 移动流程。
- `lib/utils/selection_controller.dart`：多选的唯一状态源（计数对比全选）。
- `lib/services/library_actions.dart`：音乐库侧的动作（下载 / 分享 / 删除缓存）。
- `lib/services/webdav_service.dart`：列目录 / 读写 / 复制 / 移动 / 远端流式源。
- `lib/widgets/track_status_chip.dart`：状态标签唯一定义。
