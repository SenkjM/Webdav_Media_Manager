# 02 · 网络库

> 编号 02 · 总索引：[00-INDEX.md](00-INDEX.md)  
> 代码：`lib/screens/network_library_screen.dart`、`lib/models/file_actions.dart`、`lib/screens/webdav_folder_picker_screen.dart`

网络库是 WebDAV 的浏览器：列目录、预览、把条目送进[下载队列](04-DOWNLOAD-QUEUE.md)或播放器。它**不是**曲库，也不代表本地有什么。

## 1. 核心约定：未下载 ≠「排队中」

- 用户没点过的远端文件处于 `TrackUiState.remote`：**不显示任何状态标签**，副标题写「点按下载」。
- 只有用户点按、多选或递归下载之后才入队，此时才出现「排队」「下载中」。
- 状态文案由 `lib/widgets/track_status_chip.dart` 统一给出：排队 / 下载中（带百分比）/ 就绪 / 播放中 / 错误；`remote` 返回空 widget。
- **不要**把「浏览时可见的远程文件」默认标成排队，也不要在播放路径上偷偷入队下载。

## 2. 文件动作模型

类型由后缀决定（[`FileTypeConfig`](01-DATA-MODEL.md)）：音乐 / 视频 / CUE / 普通文件。
每个类别在设置里有一个默认动作，格式为 `<类型> → <默认动作>`：

| 类别 | 默认动作 | 其它可选动作 |
|------|----------|--------------|
| 音乐 | 缓存音乐 | 流式传输（实验性，需开关）、下载 |
| 视频 | 流式传输 | 下载 |
| CUE | cue 读取 | 下载 |
| 普通文件 | 下载 | — |

- 「下载」= 落系统下载目录（`DownloadTarget.downloads`），**不是**缓存；音频缓存只由「缓存音乐」产生。
- 任何文件都可以用「下载」；缓存音乐只对音乐合法，视频那个流式传输只对视频合法。
- 判定只有一份实现：`FileActionCatalog.isAllowed` / `judgeAction`。动作与类型不匹配时**直接说明原因**，不静默换成别的动作。
- 三个入口共用同一份判定：整行点按、多选工具栏、右侧「更多」菜单。更多菜单的第一条永远是当前默认动作，并标注「设置里的默认动作」。
- 设置界面见 `file_extensions_screen.dart`：每个类别一个下拉框，选项就是上表的允许列表。

## 3. 行操作

| 操作 | 语义 |
|------|------|
| 点按文件行 | 执行该类别在设置里的默认动作（见 §2） |
| 点按已缓存音乐行 | 默认动作是缓存音乐时命中缓存即直接就绪，不会重下 |
| 点按文件夹 | 进入目录 |
| 点按 `.cue` | 默认动作是 cue 读取时进 CUE 预览流程，确认后整组下载（见 [03](03-MUSIC-LIBRARY.md)） |
| 长按任意行 | 进入多选 |
| 行尾「⋮」 | 更多操作：默认动作 + 该类别的其它动作 + 重命名 / 复制到… / 移动到… / 删除 |
| 长按文件夹 | 递归下载整个目录里的音频 |

## 4. 复制 / 移动

- 入口：单行「⋮」→「复制到…」/「移动到…」，以及多选工具栏的复制 / 移动按钮（可批量）。
- 目标由目录选择器选出（`webdav_folder_picker_screen.dart`）：浏览远端目录树、可新建文件夹、可原地确认。
- 选择器的按钮分工：**左上角是叉号（关闭选择器）**，右上角是**向上箭头（上一级，已在根目录时禁用）**与「新建文件夹」；返回键等价于上一级。顶部路径单行**可横向滚动**，长路径不会被省略号吃掉。
- **同名冲突自动改名**（`name (1).ext`），绝不静默覆盖——`Overwrite: T` 会不可逆地抹掉目标端旧文件。
- 移动文件夹时不能把它移进自己或自己的子目录（选择器禁用当前位置）。
- 传输层是 WebDAV 原生 `COPY` / `MOVE`（`WebDavService.copyPath` / `movePath`），远端自己完成，不经过本机。
- **已知限制（未做）**：移动 / 重命名远端文件后，本机音乐库里绑定旧路径的曲目不会自动跟随；重名解析需要先列一次目标目录（列目录失败时沿用原名，由服务端报错）。

## 5. 多选工具栏

- 长按进入多选；**点按行**在多选态下切换勾选，取消到最后一项时退出多选。
- 工具栏左端那个按钮是「全选」/「取消全选」，**判定用计数器对比**（选中数 == 可选总数即为全选），不看按钮按过没有：
  - 一进入多选它只是「全选」，**不显示叉号**；
  - 计数打满（无论按全选还是手动一项项点满）时它变成叉号，作用是**取消全选**，不是退出多选；
  - 任何一次手动取消都会把计数打回去，按钮随即变回「全选」。
  - 计数对比要成立，**总数必须跟着当前列表走**：`SelectionController.toggleSelectAll` 自己用传进来的 key 列表定 `total`。曾经这里只透传旧值，而音乐库从不调用 `sync`，`total` 永远是 0——`isAllSelected` 恒为假，于是「点了全选，再点多少遍还是全选」，按钮根本变不回来。
- 退出多选靠系统返回键（或点掉最后一项）。
- 剩下的动作按**选中内容的类型**出现，不摆一排禁用按钮：
  - 文件 → 「缓存音乐」（音频进缓存，随后 ingest 进音乐库）与「下载」（其余落系统下载目录）**两个独立按钮**，混选时各自只处理自己那一类；
  - 单个文件夹 → 「缓存文件夹中的音频」（递归扫描，音频进缓存）与「下载整个文件夹」（递归，全部文件落系统下载目录）也是两个独立按钮；
  - 复制到… / 移动到… 对任意选中项都可用。
- **没有播放按钮**：流式播放一次只能放一个，放个「播放全部」只会误导；要播就点那一行（或在「⋮」里选）。
- 底色铺满整宽，**滚动层在底色里面**：按钮在窄屏上横向滚动，但灰色条不会跟着内容一起被截断（曾经直接在滚动层上色，右边会露出一截空白）。
- 多选的下载**逐项按类型分发**：音乐进缓存，视频与普通文件落系统下载目录；不再把所有东西都当音频，也不再把视频塞进相册（相册在「⋮」里单独选）。

## 6. 导航与返回键

- 进入子目录后按返回键 → 回父目录。
- **多选状态下按返回键 → 只退出多选**：既不回上一页，也不回主页。
- 已在根目录时按返回键 → 交给应用壳（切主页标签 / 挂后台）。
- 实现要点：网络库在 `initState` 里向 `BackHandlerRegistry` 注册处理器（`PopScope` 在这层嵌套导航里收不到事件）；音乐库的两个多选组件同样注册，并且只在**当前路由**上生效，否则父页面的处理器会先把事件消费掉。壳层的返回语义见 [05 §3](05-AUDIO-PLAYBACK.md)。

## 7. 下载目标（这里只决定「去哪儿」）

| 条目 | 目标 |
|------|------|
| 音频（缓存音乐） | 应用音频缓存，随后 ingest 进[音乐库](03-MUSIC-LIBRARY.md) |
| 视频（⋮ → 下载到系统相册） | 系统相册 `Movies/WebdavMediaManager`（MediaStore），不进音频缓存 |
| 任何文件（下载） | 系统下载目录（MediaStore `Downloads`） |

队列状态、进度通知与失败处理见 [04](04-DOWNLOAD-QUEUE.md) 与 [07](07-NOTIFICATIONS.md)。

## 8. 尚未实现 / 未验收

- **音乐流式传输**：实验开关打开后，音乐条目会复用视频的远端流管线直接播放（不下载、不缓存、不入队），界面是独立的 [音乐流式播放页](05-AUDIO-PLAYBACK.md)（不渲染视频、无手势、控件不自动隐藏、不旋转、不画中画）。后缀被改掉、内容其实是音频的条目也会路由到这一页。**未真机验收**，封面与时长不取。取舍与坑见 [99 §3](99-IN-PROGRESS.md)。
- 上传、属性查看、批量覆盖冲突策略：见 [00 §4](00-INDEX.md) 路线图的「WebDAV 管理」。
